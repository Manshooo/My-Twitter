# Приложение (PWA)

AzzB ставится на телефон и компьютер как приложение: на Android и в Chrome, Edge или Яндекс Браузере —
через меню браузера или пункт «Установить приложение» в меню «Ещё», на iPhone — «Поделиться →
На экран „Домой“». Открывается в отдельном окне без адресной строки; ярлыки «Уведомления» и «Сообщения».

## Что кэшируется

Сервис-воркер `/sw.js` (шаблон `azzb/templates/azzb/sw.js`, вьюха `azzb.views.service_worker`):

| Что | Как |
|---|---|
| Страницы | Только из сети, через navigation preload: браузер шлёт запрос, не дожидаясь запуска воркера. Без связи — офлайн-страница `/offline/` |
| Статика с хешем в имени | Из кэша, а при промахе — из сети с сохранением в кэш |
| Статика без хеша (разработка) | Из сети, из кэша — только без связи |
| API, htmx, картинки, POST | Воркер не трогает |

Страницы и ответы API не кэшируются: в них личное (лента, сообщения), а общий телефон или выход из
аккаунта не должны оставлять их в кэше. Офлайн-страница — без темы и выбора cookie конкретного человека.

## Обновление

Список файлов для кэша — адреса статики с хешами, поэтому каждая выкладка с новыми CSS, JS или шрифтами
меняет `/sw.js`. Браузер скачивает новый воркер (он отдаётся с `Cache-Control: no-cache`), тот сразу
занимает место старого и удаляет прежний кэш. Если поменялась только офлайн-страница, поменяйте и что-нибудь в `sw.js`,
иначе браузер её не перекачает.

## Скорость

Воркер не загружает страницу дважды. В DevTools → Network она видна двумя строками: документ
«(ServiceWorker)» и запрос самого воркера (`sw.js`) — это один и тот же запрос, времена перекрываются.
Время ожидания сервера — во вкладке Timing у документа («Waiting for server response»).
Единственная издержка воркера — его запуск после простоя (браузер останавливает воркер примерно
через 30 с); navigation preload её убирает.

## Проверка

DevTools → Application: Manifest без ошибок, Service workers — `/sw.js` activated. Network → Offline
и переход по ссылке — офлайн-страница; включить сеть — страница откроется сама.

## Не сделано

Web-push (уведомления при закрытом сайте): нужны ключи VAPID, подписки в базе, рассылка из
`notifications.services.notify` и разрешение в браузере. Проверить можно только на сервере с HTTPS.
