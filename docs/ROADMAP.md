# AzzB — исследование и дорожная карта

_Составлено 2026-11-05 по итогам аудита кода (ветка `main`, `bb3dea2`) и интервью._

## 1. Итоги интервью

| Вопрос | Ответ |
|---|---|
| Цель | Живая соцсеть на azzb.ru |
| Аудитория | Открытая, 1000+ пользователей |
| Основной контент | Короткие посты (микроблог): текст + картинки |
| Фронтенд | Django-шаблоны + HTMX, jQuery постепенно убираем |
| Мобильная версия | Адаптивная вёрстка, поддомен `m.` убираем |
| Инфраструктура | VPS + nginx, SQLite, деплой вручную |
| Ресурсы | Один разработчик, работает регулярно |
| Хочется (кроме медиа, комментариев и дизайна) | Уведомления, поиск и хэштеги, репосты/цитаты, закладки, личные сообщения |
| Модерация | Жалобы и баны, блокировка, подтверждение email, закрытые аккаунты |
| Профиль и посты | Редактирование постов, баннер и вкладки, тёмная тема, опросы |
| Главная лента | «Умные» рекомендации |

**Вывод.** По сути это полноценная публичная соцсеть. Значит, главный риск не в нехватке фич, а в фундаменте. Текущий код рассчитан на десяток друзей: в API есть дыра в безопасности, ленты без пагинации, база на SQLite, тестов нет. Поэтому план начинается с фундамента, и до открытого запуска в нём обязательно стоит минимальная модерация.

## 2. Что сейчас есть

- Регистрация, вход, сброс пароля по email (SMTP mail.ru, доставка не проверена, см. проблему 17)
- Профиль: аватар (только по умолчанию, формы загрузки нет), отображаемое имя, bio, имя и фамилия, «последний визит», галочка для staff
- Подписки (`FollowThrough`), списки «Подписан на» и «Подписчики»
- Посты: только текст, создаются из профиля через AJAX, удаление, лайки
- Ленты: «Последние» (10 штук), «Горячее» (по лайкам за всё время), «Новое от подписок»
- Модель `Image` (FK на пост) уже есть, но ни при создании поста, ни при отображении она не используется
- DRF API: `profiles/`, `new-post/`, `like-post/`, `delete-post/`

## 5. План реализации

Порядок выстроен по зависимостям: страница поста нужна для комментариев, комментарии и репосты нужны для уведомлений, Redis нужен для DM и рекомендаций, менеджер видимости нужен для приватности.

### Этап 0. Фундамент (≈ 2–3 недели) — ✅ готово
A1 → A2 → A3 → A9 (тесты на права пишем сразу) → A4 → A5 + A6 → A7 → A8
**Готово, когда** API закрыт, лента пагинируется и укладывается в фиксированное число SQL-запросов на страницу, прод работает на Postgres, CI зелёный.

### Этап 1. Контент + дизайн (≈ 4–6 недель, дизайн идёт параллельно) — ✅ готово (2026-11-05)
B1, B2 → B3 → B4, B5 → B6 · параллельно C1–C4, C6 (логотип)
**Готово, когда** можно опубликовать пост с картинками, ответить на него и открыть ветку обсуждения, а сайт удобен с телефона и в тёмной теме.

### Этап 2. Минимум безопасности перед открытием (≈ 2–3 недели) — код ✅ готов (2026-11-06), сервер — в работе
E0 → E1 → E2 → E3 → E4 → C5 + E6
(E0 можно сделать в любой момент раньше: это настройка сервера и DNS, кода почти нет, а сброс пароля нужен уже сейчас. Заодно репутация IP успеет накопиться к запуску.)
**Готово, когда** письма доходят во «Входящие», регистрация требует подтверждения почты, спам упирается в лимиты, есть очередь жалоб, а правила и политика опубликованы. **Только после этого стоит звать людей публично.**

Что сделано в коде:
- **E0** — настройки почты из `.env` (по умолчанию Postfix на `localhost:25`), журнал ошибок отправки; инструкция для сервера — [`docs/deploy/mail.md`](deploy/mail.md).
- **E1** — django-allauth: вход по логину или почте, обязательное подтверждение почты, сброс и смена пароля, смена почты с подтверждением. Аккаунты, заведённые до allauth, считаются подтверждёнными (миграция `customUser.0007`).
- **E2** — лимиты allauth на вход, регистрацию, сброс пароля (кэш в PostgreSQL) и свои атомарные счётчики в PostgreSQL на посты, лайки, подписки, жалобы, выгрузку данных (`azzb/ratelimit.py`). Yandex SmartCaptcha на регистрации — включается ключами в `.env`.
- **E3** — `Block` и `Mute`: блокировка скрывает посты в обе стороны через `visible_to` и снимает подписки, заглушение убирает из лент; страница «Блокировки и заглушённые».
- **E4** — приложение `moderation`: жалобы на посты и профили, очередь `/moderation/` для группы «Модераторы», скрытие поста с причиной, бан на 1/7/30 дней или навсегда с экраном «Аккаунт заблокирован», история банов.
- **C5 + E6** — правила, политика конфиденциальности, отдельное согласие на обработку ПДн (две галочки при регистрации, время согласия хранится), архив своих данных (ZIP), удаление аккаунта.

Что осталось вне кода (перед публичным запуском):
- почта: пароль приложения mail.ru как временное решение, затем Postfix + DKIM + SPF/DMARC по `docs/deploy/mail.md`;
- сервер по [`docs/deploy/security.md`](deploy/security.md): `X-Real-IP` в nginx, ключи SmartCaptcha, `SUPPORT_EMAIL` и `LEGAL_OPERATOR` в `.env`;
- вычитка правил и политики юристом, уведомление Роскомнадзора об обработке ПДн;
- шрифты с Google Fonts — трансграничная передача IP; лучше раздавать со своего сервера.

### Этап 3. Социальные механики (≈ 4–6 недель) — в работе
D1 → D4 → D5 → D2 → D3 → D6, D7 · G1 · E5 · B7, B8

Что сделано:
- **D1** — приложение `notifications`: лайки, ответы и подписки (снятый лайк и отписка уведомление убирают). Страница `/notifications/` группирует по «что + пост + день» («eve, dan и ещё 2 лайкнули ваш пост»), ответ показывается карточкой поста. Видимость — те же правила, что у постов, плюс скрыты заглушённые. Значок со счётчиком в меню и таб-баре (вместо «Настроек»: они открываются из профиля), опрос раз в 30 с, пока вкладка видна. Открытие страницы отмечает всё прочитанным. Упоминания добавятся вместе с D2, WebSocket — в F3.
- **D4** — репост — пустой пост с `repost_of` (`is_repost`), в ленте и профиле — карточка исходного с пометкой «X сделал(а) репост»; лайк, ответ и цитата репоста достаются исходному. Отмена — мягкое удаление строки. Цитата — обычный пост с `quote_of` и карточкой цитируемого внутри (недоступный — заглушкой). Счётчик `reposts_count` (репосты + цитаты) хранится в посте. Репост виден, только если виден исходный (`visible_to`); заглушённые не всплывают и через репосты; в «Горячем» репостов нет. Скрытый модератором пост нельзя репостить и цитировать. Уведомления о репостах (группируются) и цитатах.

## 6. Что учесть в редизайне

Раз дизайн переделывается прямо сейчас, лучше сразу заложить места под будущие фичи, чтобы потом не перекраивать макеты:

1. **Навигация на 7 пунктов**: Главная, Поиск, Уведомления (с бейджем), Сообщения (с бейджем), Закладки, Профиль, Ещё. Текущая горизонтальная полоса «Горячее / Новое от подписок» столько не вместит. На десктопе нужна левая колонка, на мобильном нижний таб-бар.
2. **Вкладки над лентой** на главной: «Для вас / Подписки». Гостям показываем «Горячее».
3. **Карточка поста**:
   - аватар, имя, @логин, время, пометка «изменено»;
   - текст со ссылками на @ и #;
   - сетка медиа на 1–4 элемента;
   - блок цитаты, блок опроса;
   - строка «X сделал репост» над карточкой;
   - панель действий: ответить · репост/цитата · лайк · закладка · поделиться;
   - меню «⋯»: редактировать, удалить, закрепить, пожаловаться, заблокировать, скрыть.
4. **Composer**: поле со счётчиком, вложения с превью, alt-текст, опрос, кнопка «Опубликовать». Открывается модалкой отовсюду.
5. **Профиль**: баннер 3:1, аватар поверх него, значок 🔒 у закрытых аккаунтов, кнопки «Подписаться / Запрос отправлен / Написать / ⋯». Вкладки «Посты / Ответы / Медиа / Лайки», закреплённый пост.
6. **Страница поста**: исходный пост, ветка ответов, поле ответа.
7. **Уведомления**: элементы списка разных типов (лайк, ответ, репост, подписка, упоминание, заявка на подписку), сгруппированные.
8. **Сообщения**: две панели «список диалогов / чат» на десктопе, на мобильном они открываются по очереди.
9. **Модерация**: модалка жалобы с выбором причины, заглушка «пост скрыт», экран «аккаунт заблокирован».
10. **Тёмная тема** с первого дня: все цвета только через токены.
11. **Состояния**: пусто, загрузка (скелетоны), ошибка, «нет доступа» (закрытый профиль, блокировка).
