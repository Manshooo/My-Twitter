# Картинки в постах, аватары и баннеры: что настроить на сервере

> Это схема до A10: файлы на диске сервера. Теперь картинки хранятся в бакете Selectel, а nginx
> проксирует `/media/` в бакет — см. [docker.md](docker.md). Ниже — для разработки и истории.

С этапа 1 пользователи загружают картинки. Django их проверяет, уменьшает и пересохраняет
в WebP без EXIF (`post/media.py`), а раздаёт файлы nginx из `/var/www/azzb/media/`.

## 1. Разрешить nginx принимать большие запросы

По умолчанию nginx отклоняет тело запроса больше **1 МБ** (ошибка 413), а пост может нести
4 картинки по 10 МБ. В `server { … }` сайта azzb.ru:

```nginx
# 4 картинки по 10 МБ + текст и заголовки формы.
client_max_body_size 45m;
```

## 2. Раздача `/media/`

```nginx
location /media/ {
    alias /var/www/azzb/media/;
    # Имена файлов уникальны (uuid), содержимое по адресу не меняется — можно кэшировать надолго.
    expires 30d;
    add_header Cache-Control "public, immutable";
    # Браузер не должен угадывать тип по содержимому.
    add_header X-Content-Type-Options nosniff;
}
```

Проверить и перезагрузить:

```bash
sudo nginx -t && sudo systemctl reload nginx
```

## 3. Права на папку

uWSGI работает от `azzb_user` и пишет в `media/posts/ГГГГ/ММ/` и `media/users/user_<id>/`:

```bash
sudo chown -R azzb_user:www-data /var/www/azzb/media
sudo chmod -R u+rwX,g+rX /var/www/azzb/media
```

## 4. Проверка после выкладки

1. Опубликовать пост с JPEG с телефона: картинка не лежит на боку, в ленте видна сетка.
2. Скачать картинку из ленты: это `.webp`, в свойствах файла нет геолокации и модели камеры.
3. Пост с 4 картинками по ~8 МБ публикуется без 413.
4. Удалить пост: файлы исчезают из `media/posts/…`.

Место на диске: `du -sh /var/www/azzb/media`. Бэкап `media/` нужен вместе с бэкапом базы.
