# Этап 3: выкладка на сервер

Что выходит: уведомления, репосты и цитаты, закладки, хэштеги и упоминания, поиск, «Кого почитать»
и тренды, «Горячее» с затуханием, закрытые аккаунты, закреплённый пост, опросы, баннер и политика
cookie, обновлённые документы. Вместе с ними — наведение порядка из PR #9 (пакет `customUser`
переименован в `accounts`).

Схема сервера не меняется: nginx → uWSGI (сервис `azzb`) → PostgreSQL. Новых пакетов в
`requirements.txt` нет. Простой — несколько минут, пока идут миграции: новый код не работает со
старой схемой базы, и наоборот, поэтому сайт на это время останавливаем.

Команды — из корня проекта (`/var/www/azzb`) в виртуальном окружении проекта; сервис и пути
замените на свои.

## 0. Заранее, сайт работает

**Версия PostgreSQL — не ниже 15** (уникальный индекс уведомлений использует `NULLS NOT DISTINCT`):

```bash
sudo -u postgres psql -tAc "SHOW server_version;"
```

**Расширение `pg_trgm`** (поиск людей с опечатками). Миграция включает его сама, но для этого
пользователю базы нужно право `CREATE` на базу. Проще включить заранее от `postgres` — тогда
миграции ничего не нужно:

```bash
sudo -u postgres psql -d azzb -c "CREATE EXTENSION IF NOT EXISTS pg_trgm;"
```

**`.env`** — добавить или проверить:

```ini
# Кто ведёт сайт: ФИО или наименование ИП/организации. Без этого в правилах и политиках
# вместо оператора виден заполнитель «[ФИО или наименование оператора…]».
LEGAL_OPERATOR=
# Ящик, который вы читаете: на него ведут ссылки «Связаться» и все обращения из документов.
SUPPORT_EMAIL=
# Номер счётчика Яндекс Метрики, только цифры. Можно оставить пустым и добавить позже:
# пока номера нет, Метрика не грузится, а баннер cookie всё равно спрашивает согласие.
YANDEX_METRIKA_ID=
```

**Настоящий IP посетителя** — проверьте `location /` сайта в nginx, см. [security.md](security.md),
раздел 2. Для `uwsgi_pass` нужна строка `uwsgi_param HTTP_X_REAL_IP $remote_addr;` — без неё
посетитель может сам прислать заголовок `X-Real-IP` и обойти лимиты частоты.

## 1. Резервная копия и остановка

```bash
sudo -u postgres pg_dump --format=custom azzb > ~/azzb-before-stage3.dump
git rev-parse HEAD > ~/azzb-before-stage3.commit
sudo systemctl stop azzb
```

## 2. Код

```bash
git pull
pip install -r requirements.txt
```

Пакет `customUser` переименован в `accounts`. После `git pull` от старой папки может остаться
`customUser/` с одними `__pycache__` — удалите её, она только путает:

```bash
rm -rf customUser
```

Если код заливается через `scp`, а не `git pull`, удалите старую папку `customUser/` целиком и
залейте `accounts/`, `notifications/` и остальные изменённые папки.

## 3. Миграции и статика

```bash
python manage.py migrate
python manage.py collectstatic --noinput
python manage.py check --deploy
```

`check --deploy` выведет два предупреждения — `security.W004` (HSTS) и `security.W008`
(`SECURE_SSL_REDIRECT`). Это нормально, если перенаправление на HTTPS и заголовок
`Strict-Transport-Security` ставит nginx. Ошибок (`ERRORS`) быть не должно.

Что делают миграции, кроме новых таблиц:

| Миграция | Что происходит | Сколько занимает |
|---|---|---|
| `customUser.0013` | Включает `pg_trgm` (если ещё нет) и строит триграммные индексы по логинам и именам | Секунды |
| `post.0016` | Размечает теги и упоминания в уже опубликованных постах. Уведомления о старых упоминаниях не отправляются | Секунды на тысячи постов |
| `post.0017` | Добавляет поисковый столбец (`GENERATED … STORED`): PostgreSQL пересчитывает его для всех постов и строит индекс. Таблица постов на это время заблокирована | Секунды на десятки тысяч постов |
| `customUser.0012`, `post.0012`, `azzb.0004`, `azzb.0005` | Только названия моделей в админке, SQL не выполняется | — |

Если `customUser.0013` упала с `permission denied to create extension "pg_trgm"` — выполните
команду из шага 0 и повторите `migrate`.

## 4. Запуск

```bash
sudo systemctl start azzb
sudo systemctl status azzb --no-pager
```

## 5. Проверка

Удобнее с двух аккаунтов (А и Б) в разных браузерах.

1. **Главная** открывается, в правой колонке — поле поиска, «Тренды за сутки» (если за сутки
   были посты с тегами) и «Кого почитать».
2. **Баннер cookie** появляется в окне инкогнито; «Только необходимые» его закрывает,
   «Настройки cookie» внизу страницы открывает снова.
3. **Уведомления.** Б лайкает пост А и отвечает на него — у А через ~30 секунд на колокольчике
   появляется счётчик, на странице «Уведомления» — оба события.
4. **Репост и цитата.** Б делает репост и цитату поста А — в ленте карточка «Б сделал(а) репост»
   и пост Б с карточкой поста А внутри; у А — уведомления.
5. **Хэштеги и упоминания.** Пост с `#проверка @логинА` — тег и логин стали ссылками, страница
   тега открывается, у А — уведомление об упоминании. При наборе `@` в редакторе появляются подсказки.
6. **Поиск.** `/search/?q=…` находит пост по слову в другой форме («уведомлений» → «уведомления»),
   вкладка «Люди» — человека по части логина.
7. **Закладки.** Значок под постом, пост появляется на странице «Закладки».
8. **Опрос.** Пост с опросом, Б голосует — видит проценты; А видит результаты сразу.
9. **Закрытый аккаунт.** А включает в настройках «Закрытый аккаунт» — Б в профиле А видит
   «Это закрытый аккаунт» и кнопку «Отправить заявку»; после одобрения — посты.
10. **Закреплённый пост.** А закрепляет пост через меню «⋯» — он первый в профиле.
11. **Документы.** `/rules/`, `/privacy/`, `/privacy/consent/`, `/cookies/` открываются, оператор
    указан (не заполнитель).
12. **Письма** уходят как раньше: `python manage.py sendtestemail ваш@адрес`.

Журнал на случай ошибок:

```bash
sudo journalctl -u azzb --since "10 min ago" --no-pager | tail -50
```

## 6. Нагрузка

Открытая вкладка вошедшего пользователя раз в 30 секунд спрашивает число непрочитанных
уведомлений (`/notifications/unread/`, один лёгкий запрос к базе). Пока вкладка свёрнута, опроса
нет. На сотнях одновременно открытых вкладок это несколько запросов в секунду — для uWSGI
немного, но если процессов мало (`processes` в конфиге uWSGI), следите за `harakiri` и
временем ответа. На этапе 4 опрос заменят WebSocket.

## 7. Откат

Новые миграции необратимы без потери данных этапа 3, поэтому откат — из резервной копии:

```bash
sudo systemctl stop azzb
git checkout "$(cat ~/azzb-before-stage3.commit)"
sudo -u postgres pg_restore --clean --if-exists --dbname azzb ~/azzb-before-stage3.dump
python manage.py collectstatic --noinput
sudo systemctl start azzb
```

Всё, что пользователи успели сделать после выкладки (посты, лайки, регистрации), при откате
пропадёт — поэтому решайте быстро, пока проверяете по списку выше.
